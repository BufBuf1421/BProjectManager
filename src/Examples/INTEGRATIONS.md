# Интеграции с внешними приложениями (скрипты пользователя)

BProjectManager позволяет подключать к ярлыкам приложений **свои скрипты-интеграции**.
Это работает так же, как встроенные интеграции с Blender и Substance Painter, но
логику пишете вы: создание структур папок, экспорт данных проекта, автозапуск,
взаимодействие по API вашего DCC-приложения (ZBrush, Maya, Houdini, Marmoset и т.д.).

---

## 1. Быстрый старт

1. Добавьте ярлык приложения: кнопка **«＋»** под кнопками Blender / Substance Painter →
   выберите `.exe`, `.lnk`, `.bat` или файл проекта (например `GIM.uproject` —
   запустится через Unreal Editor, назначенный в Windows). Ярлык появится на месте кнопки.
2. Правый клик по ярлыку → **«📜 Подключить скрипт интеграции»** → выберите ваш `.js`-файл.
3. Готово:
   - при каждом запуске ярлыка скрипт может подготовить файлы и передать
     приложению аргументы командной строки (хук `getLaunchArgs`) — например,
     Inkscape откроется сразу с SVG проекта;
   - после запуска приложения вызывается хук `onLaunch` вашего скрипта;
   - действия из массива `actions` появляются в контекстном меню ярлыка
     (правый клик → «▶ Название действия»).

Готовые образцы: `examples/inkscape-integration.example.js` (полная рабочая интеграция
под Inkscape) и `examples/zbrush-integration.example.js` (шаблон для своего скрипта) —
скопируйте, переименуйте и правьте.

Дополнительно: правый клик по ярлыку → **«🔗 Расширения файлов…»** — настройте,
какие файлы открывать этим приложением двойным кликом (подробно — раздел 3).

## 2. Контракт скрипта

Скрипт — обычный Node.js-модуль:

```js
module.exports = {
  name: 'ZBrush',                        // необязательно — для логов

  // Хук ПЕРЕД запуском (необязательно). Движок вызывает его ДО старта
  // приложения. Скрипт готовит файлы и возвращает массив аргументов
  // командной строки (применяется при прямом запуске .exe):
  getLaunchArgs: async (bpm, project) => ['C:\\...\\ИмяПроекта.svg'],

  // Хук ПОСЛЕ запуска (необязательно):
  onLaunch: async (bpm, project, pid) => {},

  actions: [
    {
      id: 'unique-action-id',            // уникальный внутри скрипта
      title: 'Название в меню',
      run: async (bpm, project) => {
        // вызывается из контекстного меню ярлыка
      },
    },
    // ...сколько угодно действий
  ],
};
```

Порядок при клике по ярлыку: **getLaunchArgs → запуск приложения (с аргументами) → onLaunch**.

- `project` — `{ path: string|null, name: string|null }` — проект, выбранный в
  приложении в момент запуска/действия. Если проект не выбран — `path: null`.
- `pid` — PID запущенного процесса (или `null`, если приложение запущено через ОС).
- Хук `getLaunchArgs` применяется при запуске через spawn: `.exe`/`.com`,
  а также `.lnk`, цель которого — исполняемый файл (собственные аргументы
  ярлыка при этом сохраняются). `.url` и `.bat`/`.cmd` запускаются без
  аргументов, файлы проектов (`.uproject` и т.п.) открываются через ОС.
- Если скрипт бросит ошибку в `getLaunchArgs` — приложение всё равно
  запустится (без аргументов), а ошибка будет показана в предупреждении.

### Как запускаются разные типы ярлыков

| Что выбрано кнопкой «＋» | Как запускается |
|---|---|
| `.exe` / `.com` | Напрямую (spawn), аргументы `getLaunchArgs` передаются |
| `.lnk`, цель которого — `.exe` | Запускается цель ярлыка: аргументы ярлыка + `getLaunchArgs` |
| `.lnk`, цель — документ/папка | Через ОС, как двойной клик по ярлыку |
| `.bat` / `.cmd` | Через `cmd.exe`, без аргументов |
| Любой другой файл (`GIM.uproject`, `.psd`, ...) | Через системную ассоциацию Windows: `.uproject` откроется в Unreal Editor |

> Прямой `spawn` не-исполняемых файлов невозможен — Windows отвечает ошибкой
> «spawn EFTYPE», поэтому файлы проектов всегда запускаются через ассоциацию ОС.

Иконка ярлыка `.lnk` берётся из его цели (у самого `.lnk` Windows отдаёт
«битую» иконку). У ранее добавленных ярлыков иконка починится автоматически
при следующем запуске приложения.

Скрипт загружается заново при каждом запуске/действии — **правки подхватываются
сразу, перезапуск BProjectManager не нужен** (кроме случая, когда файл открыт
внешней программой в момент записи).

## 3. Ассоциации расширений файлов

Каждому ярлыку можно назначить **расширения файлов**, которые он открывает.
Тогда двойной клик по такому файлу (в файловом менеджере и в File overview)
запускает это приложение с файлом, а не системный обработчик
(например, `.svg` откроется в Inkscape, а не в браузере).

### Как настроить

1. Правый клик по ярлыку → **«🔗 Расширения файлов…»**.
2. Введите расширения через запятую (можно с точками, регистр не важен):
   `svg, inx, psd`
3. Сохраните. Текущий список виден в меню ярлыка («🔗 Открывает: …»)
   и в подсказке к кнопке.

Файлы с этими расширениями автоматически появляются в **File overview**
вместе с `.blend` и `.spp` — с иконкой приложения.

### Приоритет открытия при двойном клике

1. Ассоциация ярлыка (расширение найдено среди exts пользовательских ярлыков);
2. встроенные типы: `.blend` → Blender, `.spp` → Substance Painter (из настроек);
3. системный обработчик ОС.

Нюансы:

- Лучше всего для ассоциаций подходит **.exe** (файл передаётся ему аргументом).
  Ярлык `.lnk`, цель которого — `.exe`, тоже работает: цель разрешается
  автоматически. Если приложение — не исполняемый файл (`.url`, документ),
  файл откроется системным обработчиком ОС.
- При открытии файла скрипт-интеграция ведёт себя так: `onLaunch` вызывается,
  а `getLaunchArgs` — НЕТ (файл уже выбран явно, его аргументы приоритетнее).
- Ассоциации хранятся в `customApps.json` рядом с остальными полями ярлыка.

## 4. API — объект `bpm`

### Информация

| Свойство | Описание |
|---|---|
| `bpm.version` | Версия API (`'1.1.0'`) |
| `bpm.appName` | Имя ярлыка, из которого запущен скрипт |
| `bpm.appPath` | Путь к исполняемому файлу ярлыка |
| `bpm.path` | Модуль `path` Node.js (`bpm.path.join(...)`) |
| `bpm.project` | `{ path, name }` текущего проекта |

### Данные проекта

| Метод | Описание |
|---|---|
| `bpm.getProjectData()` | Содержимое `project.json` выбранного проекта (автовосстановление при повреждении): `{ name, id, createdAt, status, archived, tags, tasks, notes, favorite }`. Вернёт `null`, если проект не выбран. |

### Файлы и папки — `bpm.fs`

| Метод | Описание |
|---|---|
| `readFile(file, encoding?)` | Прочитать файл (по умолчанию `utf8`) |
| `writeFile(file, content)` | Записать файл |
| `appendFile(file, content)` | Дописать в конец файла |
| `readJson(file)` | Прочитать JSON |
| `writeJson(file, data, spaces?)` | Записать JSON (по умолчанию 2 пробела) |
| `ensureDir(dir)` | Создать папку (включая родителей) |
| `ensureFile(file)` | Создать файл (включая папки) |
| `exists(p)` | Существует ли путь |
| `stat(p)` | Статистика файла/папки (`mtime`, `size`...) |
| `copy(src, dest)` | Скопировать (перезаписывает) |
| `move(src, dest)` | Переместить (перезаписывает) |
| `remove(target)` | Удалить файл/папку рекурсивно |
| `list(dir)` | Содержимое папки: `[{ name, path, isDirectory }]` |

### Запуск программ — `bpm.launch`

| Метод | Описание |
|---|---|
| `spawn(execPath, args?, opts?)` | Запустить программу (detached). Возвращает PID. `opts.cwd` по умолчанию — папка проекта |
| `open(target)` | Открыть файл/папку системным обработчиком (как двойной клик) |

### Диалоги — `bpm.dialog`

| Метод | Описание |
|---|---|
| `message(text, title?)` | Информационное окно |
| `confirm(text, title?)` | Вопрос Да/Отмена → `boolean` |
| `pickFile(filters?, title?)` | Выбор файла → путь или `null` |
| `pickDirectory(title?)` | Выбор папки → путь или `null` |
| `showToast(text)` | Всплывающее уведомление внизу экрана |

### Прочее

| Метод | Описание |
|---|---|
| `bpm.clipboard.writeText(text)` / `.readText()` | Буфер обмена |
| `bpm.shell.showItemInFolder(p)` | Показать файл в проводнике |
| `bpm.shell.openExternal(url)` | Открыть ссылку в браузере (только http/https) |
| `bpm.settings.get()` | Настройки приложения (`blenderPath`, `substancePath`, `projectsPath`, ...) — только чтение |
| `bpm.log(...)` | Лог в консоль main-процесса |

Кроме `bpm` в скрипте доступен стандартный `require` Node.js: `fs`, `path`, `http`,
`child_process` и любые установленные модули.

## 5. Пример: интеграция с ZBrush

```js
module.exports = {
  name: 'ZBrush',

  onLaunch: async (bpm, project) => {
    if (!project.path) return;
    // Готовим папки под ZBrush в каждом проекте
    await bpm.fs.ensureDir(bpm.path.join(project.path, 'ZBrush'));
  },

  actions: [
    {
      id: 'export-tasks',
      title: 'Экспорт задач в tasks.txt',
      run: async (bpm, project) => {
        const data = await bpm.getProjectData();
        const tasks = data?.tasks || [];
        const text = tasks.map((t, i) => `${i + 1}. [${t.done ? 'x' : ' '}] ${t.text}`).join('\n');
        await bpm.fs.writeFile(bpm.path.join(project.path, 'tasks.txt'), text);
        await bpm.dialog.message('Сохранено: tasks.txt');
      },
    },
  ],
};
```

## 6. Пример: Inkscape — SVG с именем проекта (пошагово)

Готовый скрипт: `examples/inkscape-integration.example.js`.

**Результат настройки:** вы выбираете проект в дереве, кликаете по ярлыку Inkscape —
и Inkscape открывается с файлом `<Имя проекта>.svg`, лежащим в папке проекта.
Если файла ещё не было — он создаётся автоматически (шаблон 1920×1080 с белым фоном
и одним слоем). Существующий файл НИКОГДА не перезаписывается — если SVG уже был,
просто откроется он самый (вся ваша работа сохранится).

### Шаг 1. Установите Inkscape

Обычно это `C:\Program Files\Inkscape\bin\inkscape.exe`.
Проверьте путь: правый клик по ярлыку Inkscape на рабочем столе → «Свойства» →
поле «Объект».

### Шаг 2. Добавьте ярлык в BProjectManager

Кнопка **«＋»** под кнопками Blender / Substance Painter → выберите
`inkscape.exe`. Ярлык появится на месте плюсика.

### Шаг 3. Подключите скрипт интеграции

Правый клик по ярлыку Inkscape → **«📜 Подключить скрипт интеграции»** →
выберите файл `examples/inkscape-integration.example.js`
(можно скопировать его куда угодно и переименовать — например `inkscape.js`).

### Шаг 4. Ассоциация расширений (чтобы .svg открывался двойным кликом)

Правый клик по ярлыку Inkscape → **«🔗 Расширения файлов…»** → введите
`svg` → Сохраните. Теперь `.svg`-файлы видны в File overview вместе с
`.blend`/`.spp`, а двойной клик по ним (в файловом менеджере и File overview)
открывает файл именно в Inkscape, а не в браузере.

### Шаг 5. Пользуйтесь

1. Выберите проект в дереве (например `ElectricShield_00000001`).
2. Кликните по ярлыку Inkscape.
3. В папке проекта появится `ElectricShield.svg` (если его не было),
   и он же откроется в Inkscape.

Дополнительно в контекстном меню ярлыка (правый клик) появятся действия:

| Действие | Что делает |
|---|---|
| ▶ Создать / открыть SVG проекта | Создаёт SVG (если нет) и открывает его в Inkscape без клика по ярлыку |
| ▶ Резервная копия SVG (с датой) | Копирует `Имя.svg` → `Имя_2026-10-04_14-30.svg` рядом |
| ▶ Показать SVG в проводнике | Открывает папку проекта с выделенным файлом |

### Как это работает внутри

```
Клик по ярлыку Inkscape
        │
        ▼
Движок BProjectManager загружает скрипт и вызывает getLaunchArgs(bpm, project)
        │
        ▼
Скрипт: имя проекта ← project.json (без индекса папки)
        склеивает путь <папка проекта>/<Имя>.svg
        файла нет?  → создаёт из шаблона (существующий не трогает)
        возвращает ["C:\…\ElectricShield.svg"]
        │
        ▼
Движок запускает: inkscape.exe "C:\…\ElectricShield.svg"
        │
        ▼
После запуска вызывается onLaunch (пишет лог)
```

Имя берётся из `project.json`, поэтому папка `ElectricShield_00000001`
даёт файл `ElectricShield.svg` — без служебного индекса. Символы,
запрещённые в именах файлов Windows (`\ / : * ? " < > |`), заменяются на `_`.
Если проект не выбран — Inkscape откроется пустым (с подсказкой;
подсказку можно отключить константой `SHOW_DIALOG_WHEN_NO_PROJECT = false`
в начале скрипта). Размер холста меняется константами `SVG_WIDTH` / `SVG_HEIGHT`.

Этот же скрипт — образец для своих интеграций: скопируйте его и замените
логику создания файла и аргументы запуска под своё приложение (Photoshop —
открывать `.psd`, Krita — `.kra`, Marmoset — `.mtoolset` и т.д.).

## 7. Отладка

- `console.log` и `bpm.log(...)` пишут в консоль **main-процесса**.
  Чтобы её увидеть: запустите приложение из терминала (`npm start`) или
  откройте DevTools main-процесса (если включено в вашей сборке).
- Ошибки синтаксиса в скрипте не мешают запуску приложения — появится
  предупреждение «скрипт интеграции сообщил об ошибке».
- Битый скрипт виден сразу: в контекстном меню ярлыка появится пункт
  «⚠️ <текст ошибки>».

---

## 8. Важно о безопасности

Скрипты выполняются **с полными правами вашего пользователя** — это та же модель,
что у аддонов Blender или плагинов Figma: код имеет доступ к файлам и сети.
Подключайте только собственные скрипты или скрипты из проверенных источников.
Хранилище ярлыков: `%APPDATA%/BProjectManager/customApps.json` (Windows).
